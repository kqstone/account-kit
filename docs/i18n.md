# 国际化 (i18n)

`account-kit` 0.3.0 起，后端错误/成功文案与 Vue/React UI 包共用两套目录：`zh-CN` 与 `en`。默认语言是 **简体中文**（`zh-CN`）。请求不带任何语言信息时也用它。

机器字符串不翻译：`SESSION_REPLACED`（字符串 `detail` 原样）、错误码、审计事件名。

宿主 `mailer(to, purpose, code, language)` 回调仍接收 `"zh"` / `"en"`（与邮件模板文件名后缀一致），不是 `"zh-CN"`。

---

## 语言解析顺序

`mount_account` 注册纯 ASGI 中间件（不是 `BaseHTTPMiddleware`），并在路由 `Depends` 上兜底，把规范化后的语言写入 `ContextVar`。

顺序：

1. `config.locale_resolver(request)`（返回非空则采用）
2. 请求头 `config.locale_header`（默认 `X-Locale`）
3. 查询参数 `config.locale_query`（默认 `locale`）
4. `Accept-Language`，仅当 `config.negotiate_accept_language=True`（默认关）
5. `config.default_locale`（默认 `"zh-CN"`）

规范化：`zh`、`zh_CN`、`zh-cn`、`zh-Hans`、`zh-*` → `zh-CN`；`en`、`en-*` → `en`。不支持的标签回落到 `default_locale`。

```python
AccountKitConfig(
    jwt_secret="...",
    default_locale="zh-CN",
    supported_locales=("zh-CN", "en"),
    locale_header="X-Locale",
    locale_query="locale",
    negotiate_accept_language=False,
    locale_resolver=None,  # 例如从 cookie / JWT 读
    messages_override=None,  # {"zh-CN": {"INVALID_CREDENTIALS": "自定义文案"}}
    localize_validation=False,  # opt-in：422 增加顶层 code=VALIDATION_ERROR
)
```

覆盖表按 locale 深合并到内置目录。kit 自己的出生年月校验（`profile.py`）始终走目录，与 `localize_validation` 无关。

## 错误响应形状

kit 抛出 `AccountError`（`HTTPException` 子类）。`detail` **类型保持历史形状**：原来是字符串的仍是字符串，原来是对象的仍是对象，并保留 `captcha_required`、`retry_after`、`challenge_token`、`device_name`、`attempts_left` 等附加字段。处理器只对 `AccountError` 注册，在顶层加上 `code`；有插值时再加 `params`。

字符串形：

```json
{"detail": "用户名或密码错误", "code": "INVALID_CREDENTIALS"}
```

对象形：

```json
{
  "detail": {
    "code": "CAPTCHA_REQUIRED",
    "message": "需要图形验证码",
    "captcha_required": true
  },
  "code": "CAPTCHA_REQUIRED"
}
```

宿主自己 `raise HTTPException(...)` **不会**被改写，也没有顶层 `code`。

完整错误码表见 [api.md](api.md#8-通用错误响应与业务错误码)。成功 `StatusResponse.detail`（如「验证码已发送」）同样走目录。

## 邮件

请求体 `language` 默认 `None`。显式传入合法值（`zh` / `zh-CN` / `en` / `en-*`）则用之，否则跟随本次请求语言。模板文件名仍是 `*_zh.html` / `*_en.html`；`email_template_map` 的 `{lang}` 展开为 `"zh"` / `"en"`。

## UI（Vue / React）

字典 key 为 `"zh-CN"` / `"en"`。`resolveLocale` 把旧的 `language="zh"` 映射到 `zh-CN`。

组件文案合并顺序（后者覆盖前者）：

1. 内置 `defaults[locale]`
2. Provider / 插件的 `messages[locale]` 对应段（`forms` / `profile` / `twoFactor`），以及同 locale 下的 `errors`
3. 组件自己的 `labels` prop

语言优先级：组件 `language` prop > Provider / 插件 locale（或 `i18n` 实例的当前语言）> 默认 `zh-CN`。

宿主覆盖类型：

```ts
type AccountMessagesOverride = Partial<Record<KitLocale, DeepPartial<{
  forms: FormLabels
  profile: ProfileLabels
  twoFactor: TwoFactorLabels
  errors: Record<string, string>
}>>>
```

`formatError` / `twoFactorErrorMessage` 走同一套合并后的 `errors` 表。`labels` 仍可作为插件 / Provider 上 `messages` 的别名（不推荐）。

### Vue

```ts
import { accountKitI18n, provideAccountI18n, followVueI18n, createAccountClient } from "@kqstone/account-ui-vue"

app.use(accountKitI18n({
  locale: "zh-CN",
  messages: {
    "zh-CN": { forms: { login: "登入" }, errors: { INVALID_CREDENTIALS: "账号或密码不对" } },
  },
}))

// 对接 vue-i18n（duck-typed，不 import vue-i18n）：
app.use(accountKitI18n({ i18n }))
// 或 setup 里：
provideAccountI18n(followVueI18n(i18n), messages)

const client = createAccountClient("/api/auth", {
  getLocale: followVueI18n(i18n), // 每请求带 X-Locale
})
```

`LoginForm` / `RegisterForm` / `ResetPasswordForm` 都有 `language` 与 `labels`。

### React

```tsx
import { AccountKitProvider, followI18next, createAccountClient } from "@kqstone/account-ui-react"

<AccountKitProvider
  locale="zh-CN"
  messages={{
    "zh-CN": { forms: { login: "登入" }, errors: { INVALID_CREDENTIALS: "账号或密码不对" } },
  }}
>
  {children}
</AccountKitProvider>

// 对接 i18next：传入实例即可，Provider 内部订阅 languageChanged（不必再手写 subscribe）：
<AccountKitProvider i18n={i18n}>{children}</AccountKitProvider>

const client = createAccountClient("/api/auth", {
  getLocale: () => i18n.language,
})
// followI18next(i18n) 仍导出，含 getLocale / subscribe，给需要自行订阅的宿主用。
```

`AccountApiError.code` 先读 `detail.code`，再读顶层 `body.code`。`formatError(error, labels, locale)`：有 code 则用本地表（支持 `{params}` / `attempts_left` 等插值），否则用服务端文案，再否则通用「请求失败」。`formatDateTime` 按 locale 格式化。

Peer 依赖不变：Vue 包只要 `vue`，React 包只要 `react`。
